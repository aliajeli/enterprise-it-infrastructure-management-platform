# Testing strategy

> **Current evidence (0.1.223): [run 45480884339](https://github.com/aliajeli/enterprise-it-infrastructure-management-platform/actions/runs/45480884339) on 0.1.222 passed Windows functional/archive/Vault and disposable fast/full assembly/migration, Linux and payload publish jobs; four credential-transport security probes failed and overall CI failed. These fixtures do not prove secure production transport, native Windows Server acceptance, or installer readiness. Current details: [HANDOVER](HANDOVER.md).**


M0/M1 automated validation and PostgreSQL integration tests exist in the repository and are executed by GitHub Actions. The tests added for branch lifecycle and administrator password recovery must pass on the exact M1 completion head before merge. The following additional validation remains required before production: strict TS, lint; unit tests for authorization, validators, crypto envelopes, state transitions, version classification and update policy; PostgreSQL integration including constraints, migration round trips/forward compatibility, lease expiry, concurrency, replay and recovery; API/WebSocket authorization and reconnect; Windows .NET agent build and tests, malicious task rejection and disconnect recovery; Excel import preview, duplicate/error handling; Playwright authenticated workflows and accessibility at 1280x720, 1366x768, 1600x900, 1920x1080, 2560x1440, 3840x2160, tablet and mobile.

Windows VM tests: clean offline install with no developer tools, upgrade from supported versions, failed installation at each stage, restore/rollback, migration failure and data loss accounting, uninstall retaining data, service restart/reboot, user-session notification, bridge authentication/origin/path attacks, and package contents/manifest/checksum parity. Verify Windows service privilege isolation, firewall and SMB/SCM behavior across GIG/OKCS with no trust. GitHub release tests cover concurrent version allocation, branch normalization, multi-commit pushes, merges, tag collisions, retries, dispatch failure and partial drafts. Hardware tests cover both NVR model/firmware variants and channel disappearance, MikroTik and installed TeamViewer version. All tests report actual environment, commands and outcomes; absence of hardware is a release blocker for capabilities that claim to support it, not a passed test.

Verify no published release exists on any required gate failure and that successful artifacts are downloadable and install offline. ## Owner-approved three tiers — 2026-11-18
These tiers supersede any reading that real hardware is a universal blocker for unrelated changes. **All tests below are proposed, not executed.**

**Tier 1 — every commit:** lint/typecheck; unit, mocked integration, PostgreSQL database tests, API/WSS authentication/authorization, security, agent protocol, simulated deployment targets, UI/Playwright where applicable, and build/packaging validation where available. Per-commit isolated pipeline marks missing applicable checks unavailable/failed, never passed. During approved bootstrap, only applicable validation runs and no fake installer/release is published.

**Tier 2 — Windows build and installer:** controlled Windows VMs/dedicated runners test exact artifact for clean and offline install without developer tools, all five service startups/readiness, repair and upgrade, migration, backup/restore, rollback/fault injection, uninstall data retention, Agent installation/update; separately authorized Desktop Bridge PoC security tests when in scope. After bootstrap, the mandatory releasable commit gate includes actual standalone installer build and relevant isolated Windows validation. If an essential runner or test is unavailable, no successful release for that commit; retry when available. A platform limitation or failed test is recorded, not waived silently.

**Tier 3 — real hardware/environment:** test the applicable integration upon implementation/change and before marking that capability compatible: Hikvision DS-7732NI-K4 and DS-7732NXI-K4 with actual firmware/ISAPI; MikroTik RouterOS/Winbox; installed TeamViewer LAN version; GIG and OKCS explicit-credential no-trust SMB/ADMIN$/SCM; real checkout and Store Commerce. Record model/firmware/environment, test date, operator, result, limitations and evidence. If unavailable, that capability remains **unverified** and cannot be advertised or approved as compatible. Hardware absence does not block unrelated UI/documentation changes; release notes retain the limitation. Never report a mock as hardware success.


## Worker queue validation requirements

The first Worker slice includes unit tests for retry backoff and attempt limits. Before any discovery handler is enabled, add PostgreSQL integration tests for concurrent `SKIP LOCKED` claims, single-owner leases, heartbeat expiry, stale-worker completion rejection, crash recovery, retry exhaustion, cancellation races and transaction rollback. Run the Worker on the target Windows VM as an independently supervised service and verify readiness, graceful shutdown, restart and database outage recovery. The current empty-handler worker must never claim queued jobs.


## Worker queue PostgreSQL integration coverage — 2026-11-19
The Worker suite now includes disposable-PostgreSQL integration tests for concurrent single-run claims, owner-bound heartbeat/completion, stale lease rejection (including cancellation acknowledgement), expired-lease recovery and reclaim, retry requeue followed by max-attempt failure, cancellation precedence over retry exhaustion, and transaction rollback. These tests are gated on a `DATABASE_URL` containing `/platform_test`; they must be observed passing on the exact CI head before the queue foundation is considered validated. No handler is enabled by this test work.
